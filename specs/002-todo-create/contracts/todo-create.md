# Todo作成画面 契約

## 画面の起動と終了

- Todo一覧の作成操作からTodo作成画面を開く。
- 成功時のみ画面を閉じ、Todo一覧へ戻って一覧を再読込する。
- 入力エラー、保存先の問題、競合、保存失敗では画面を閉じず、タイトルと本文を保持して利用者に理由と対処を示す。

## 画面操作

| Area | Contract |
|---|---|
| Title | 必須のテキスト入力。空白のみ、`.`、`..`、`/`、`\`、U+0000〜U+001F、U+007Fは拒否する。Windows固有の禁止文字・予約名を一律拒否しない。無効な値を自動置換しない |
| Body | 任意のMarkdownテキスト。入力表示で編集し、プレビュー表示では編集不可 |
| Mode toggle | 入力／プレビューを切り替えても、タイトル・本文を保持する |
| Tag suggestion | 本文先頭または空白の直後にある、コード外・未エスケープの`#`を検出する。`#`から次の空白または本文末尾までを検索文字列として登録済みタグを部分一致で絞る。選択時はカーソルを含むタグトークン全体を`#<タグ>`で置換し、周囲の本文を保持する。一致なしのEnterは入力中タグを確定する |
| Note suggestion | コード外・未エスケープの`[[`を検出する。同じ行の最初の`]]`または行末までを検索文字列として保存先配下のMarkdownタイトルを部分一致で絞る。選択時はカーソルを含むWikiリンクトークン全体を`[[<タイトル>]]`で置換し、周囲の本文を保持する。一致なしのEnterではリンクを挿入しない |
| Create | 検証後にTodo作成Repositoryを呼び出す。処理中は重複送信を防ぎ、失敗時は再入力なしで再試行できる |

画面レイアウトと切替操作は[作成画面イメージ](../../../docs/screen_image/02-todo-create.svg)および[プレビュー画面イメージ](../../../docs/screen_image/03-todo-preview.svg)を参照する。

## Todo作成Repository境界

入力は`TodoDraft(title, content)`。結果は[data-model.md](../data-model.md#todocreateoutcome)で定義する`TodoCreateOutcome`とする。

Repositoryは候補取得、作成可能なタイトルの検証、Todo本文の組み立てを担う。AndroidのURIやContentResolverを画面に公開しない。

### 保存契約

1. 空白タイトル、`.`、`..`、`/`、`\`、U+0000〜U+001F、U+007Fを検証し、入力を変更せず該当文字と対処を返す。Windows固有の禁止文字・予約名は一律に拒否せず、SAF提供元に判定を委ねる。
2. 保存先直下の`<title>.md`を確認し、既存の場合は作成を拒否する。サブフォルダーの同名ファイルは競合としない。
3. 保存本文の先頭に独立した`#todo`行を一度だけ置く。
4. 新規ファイルのみ作成し、既存ファイルを開いて上書きしない。
5. 保存先未設定、読取／書込権限不足、提供元の拒否、書込失敗を型付き失敗として返す。成功時以外に画面遷移させない。

## Android MethodChannel境界

既存の`todo_sdd/folder_access`チャネルを拡張し、新規Markdown作成操作を提供する。引数は保存済みツリーURI、タイトルから生成したファイル名、UTF-8 Markdown本文。成功応答は作成した相対パスを返し、UIが保存完了を認識できるようにする。

ネイティブ側は次を保証する。

- URIが有効なツリーURIで、アプリが永続的な読取・書込権限を持つことを確認する。
- フォルダー選択時に読取・書込権限を要求し、SAFのpersistable grantを保存する。アプリ再起動後も権限を利用できることを結合検証し、拒否・失効時は権限不足を返す。
- 既存実装と同じサポート対象のDocument providerおよび選択ツリーの範囲内でのみ動作する。
- 作成対象はツリー直下で、ファイル名は`<title>.md`。区切り文字等を含む相対パスを受け付けない。
- 既存の同名Documentを置換・truncateしない。作成前に直下の同名ファイルを拒否し、SAFが新規Documentを返す場合は返却名が要求名と一致することも検証する。
- 提供元が要求名と異なる名前のDocumentを作成した場合、今回作成したDocumentだけを削除し、競合を返す。削除に失敗した場合は残存したDocumentのパスをエラー詳細に含める。
- ルートの`FLAG_DIR_SUPPORTS_CREATE`と作成後Documentの`FLAG_SUPPORTS_WRITE`を確認する。新規Documentへのopen/write/closeが失敗した場合、削除対象は今回作成したDocumentだけとし、後始末にも失敗した場合はその状態をエラー詳細に含める。

| Error category | Expected caller behavior |
|---|---|
| `invalid_uri` / `unsupported_provider` | 作成を拒否し、保存先の再設定を案内する |
| `permission_denied` | 作成を拒否し、作成画面から既存のフォルダー選択フローを開く再選択操作を示す。選択後、読取・書込権限の取得と永続化が成功した場合にのみ保存先設定を更新する。選択をキャンセルした場合は旧設定と入力値を保持する |
| `invalid_name` | アプリ側で拒否した文字、または提供元が返したファイル名拒否の理由と対処を示し、タイトル・本文を保持する。提供元が詳細理由を返さない場合は、提供元による拒否と保存先・タイトルの確認方法を示す |
| `already_exists` | 既存ファイル名を示し、既存データを変更せず入力に戻る |
| `write_failed` | 保存失敗を表示し、入力を保持する。後始末に失敗して部分Documentが残る場合は相対パスを示し、不完全ファイルであることと、利用者が保存先で確認・手動削除する必要があることを案内する |
