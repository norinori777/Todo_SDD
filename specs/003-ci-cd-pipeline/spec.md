# Feature Specification: CI/CD Validation and Review Gate

**Feature Branch**: `003-ci-cd-pipeline`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: 「コミットを push したときと Pull Request を作成・更新したときに、`flutter analyze`、`flutter test`、Android build を実行する。失敗した検査は失敗として表示する。Pull Request では `pr-review.agent.md` によるレビューコメントを投稿し、すべてのチェック成功後に人間が確認してマージする。」

## Clarifications

### Session 2026-11-09

- Q: どのブランチへの push で自動検証を実行しますか？ → A: すべてのブランチへの push で実行し、Pull Request 作成・更新時にも実行する。
- Q: 自動レビューの実行またはレビューコメントの投稿が未完了でも、3つの検査が成功していれば Pull Request をマージ可能にしますか？ → A: 3つの検査に加えて、自動レビュー完了とコメント投稿もマージ必須条件とする。
- Q: CI の検査と自動レビューに与える権限を、各処理に必要な最小限に制限しますか？ → A: 検査は読み取り専用、自動レビューはコメント投稿のみ可能とする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Pushした変更を検証する (Priority: P1)

開発者が変更をリポジトリへ push すると、変更が基本的な品質基準と Android 向けビルドを満たすかを確認できる。

**Why this priority**: Pull Request を作る前にも変更の問題を早く発見でき、失敗した変更を成功と誤認することを防ぐため。

**Independent Test**: 成功する変更と、各検査で失敗する変更をそれぞれ push し、3つの結果が表示され、失敗が成功扱いにならないことを確認する。

**Acceptance Scenarios**:

1. **Given** リポジトリのブランチに新しいコミットが push された状態、**When** 自動検証が完了する、**Then** `flutter analyze`、`flutter test`、Android build の結果がそれぞれ確認できる。
2. **Given** いずれかの検査が失敗する変更、**When** 検証が完了する、**Then** 失敗した検査と全体の結果が失敗として表示される。

### User Story 2 - Pull Requestを検証して人間が判断する (Priority: P1)

開発者が Pull Request を作成または更新すると、同じ検査とレビューが行われる。担当者は結果を確認してからマージを判断できる。

**Why this priority**: Pull Request の変更内容とレビュー結果を照合し、すべての必須チェックが成功した後に人間が最終判断するため。

**Independent Test**: Pull Request を作成・更新し、push時と同じ3検査の結果と `pr-review.agent.md` に基づくレビューコメントを確認した後、チェック失敗時と成功時のマージ可否を確認する。

**Acceptance Scenarios**:

1. **Given** Pull Request が作成または更新された状態、**When** 自動処理が完了する、**Then** 最新の変更に対する3検査の結果とレビューコメントが Pull Request 上で確認できる。
2. **Given** 最新の変更に対する必須チェックが1つでも失敗している、または自動レビューもしくはコメント投稿が未完了の状態、**When** 人間がマージしようとする、**Then** マージできない。
3. **Given** すべての必須チェックが成功し、レビューコメントが確認できる状態、**When** 人間が変更を確認してマージを選択する、**Then** 人間の判断によってマージされ、自動マージは行われない。

### Edge Cases

- Pull Request の更新後に新しい検査が実行中または失敗中の場合、以前のコミットに対する成功結果を最新の変更の成功として扱わない。
- 検査を開始できない、または実行中にエラーが発生した場合、成功として扱わず、失敗または未完了であることを確認できる。
- レビューコメントを投稿できない場合、レビューが完了したと誤認させず、投稿できなかったことを明示する。
- 検査の再実行後も、マージ判断には Pull Request の最新の変更に対応した結果だけを用いる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: すべてのブランチへのコミットの push を契機に、`flutter analyze`、`flutter test`、Android build の3検査を実行しなければならない。Pull Request に関連するブランチへの push でも実行する。
- **FR-002**: Pull Request の作成と更新を契機に、FR-001と同じ3検査を実行しなければならない。
- **FR-003**: 各検査の実行結果を個別に確認できなければならない。
- **FR-004**: いずれかの検査が失敗または実行不能の場合、その検査と検証全体を成功として表示してはならない。失敗または実行不能の状態を明示しなければならない。
- **FR-005**: Pull Request の検査結果は、その Pull Request の最新の変更に対応していなければならない。過去の変更に対する成功結果で最新の変更を成功と判定してはならない。
- **FR-006**: Pull Request の作成・更新時に、`pr-review.agent.md` の手順に基づいてレビューし、結果を Pull Request のコメントとして投稿しなければならない。指摘がない場合もレビュー完了を確認できる結果を投稿しなければならない。
- **FR-007**: レビューまたはコメント投稿が完了しない場合、その状態を明示し、レビュー完了として表示してはならない。
- **FR-008**: 3つの検査がすべて成功し、自動レビューとレビューコメントの投稿が完了するまで、Pull Request をマージできないようにしなければならない。
- **FR-009**: すべての必須チェックが成功した後も自動マージを行わず、人間が変更とレビュー結果を確認してマージを判断できなければならない。
- **FR-010**: CI の検査にはリポジトリの読み取り権限のみを与え、自動レビューにはレビューコメント投稿に必要な権限のみを与えなければならない。自動処理にソース変更またはマージの権限を与えてはならない。

### Key Entities

- **Pushされた変更**: 検証対象となるコミットとブランチ。
- **検査結果**: 対象の変更、検査名、実行状態、成功・失敗を表す結果。
- **Pull Request**: 検査とレビューの対象となる変更、および最新の変更の状態。
- **レビューコメント**: Pull Request に投稿されるレビュー結果。指摘の有無とレビュー完了状態を示す。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: push および Pull Request の作成・更新の対象イベントの100%で、指定された3検査の結果を確認できる。
- **SC-002**: いずれかの検査が失敗または実行不能となった場合、該当する実行の100%が成功以外の状態として確認できる。
- **SC-003**: Pull Request の作成・更新の100%で、最新の変更に対応する3検査の結果とレビューコメントまたはレビュー未完了状態を確認できる。
- **SC-004**: 必須チェックがすべて成功する前にマージされた Pull Request がなく、各マージで人間によるレビュー確認が行われる。
- **SC-005**: CI の検査が読み取り権限のみを持ち、自動レビューがコメント投稿以外のリポジトリ変更・マージ権限を持たないことを設定で確認できる。

## Assumptions

- 「同じ検査」は `flutter analyze`、`flutter test`、Android build の3つを指す。
- 検査対象となる Android build の具体的な種類は、プロジェクトで既に利用しているビルド設定に従う。
- マージ前の必須チェック制御を利用できるよう、対象ブランチに対してリポジトリのマージ保護設定を行う。
- Pull Request のレビューコメントは既存の `pr-review.agent.md` に定義されたレビュー手順と投稿形式に従う。自動レビューに必要な実行権限がない場合は成功扱いにしない。
- 本機能の範囲は push / Pull Request 時の検査、レビュー結果の提示、およびマージ条件であり、チェック失敗の自動修正や自動マージは含まない。
