# 実装計画: Todo一覧画面

**ブランチ**: `specs/001-todo-list`（セットアップの機能識別子: `001-todo-list`） | **日付**: 2026-11-01 | **仕様**: [spec.md](./spec.md)

## 概要

利用者が設定したフォルダー以下のMarkdownからTodoを抽出し、検索、関連ノートの参照、完了・未完了の切り替えを行うAndroid向けFlutter画面を設計する。Markdownを正本とし、対象箇所以外を保持して保存する。作成・編集・詳細・設定画面は別機能であり、公開境界で連携する。

この計画は最新の仕様に基づく設計であり、実装やAndroid保存先での安全性が検証済みであることを意味しない。実装作業と未検証の公開条件は[タスク](./tasks.md)で管理する。

## 技術コンテキスト

- **言語 / バージョン**: Dart 3.11.5、Flutter 3.41.7を`pubspec.yaml`で指定済み。Android向けの権限・ファイル操作は対象提供元で検証する。
- **主な依存**: Flutter SDK、`flutter_test`、`integration_test`、`yaml`、`path`、Windows用の`ffi`と`win32`を指定済み。MarkdownやAndroidアクセスに追加依存が必要な場合は、保持・権限要件を評価する。
- **保存**: 利用者指定フォルダーの既存Markdown。DB、サーバー、外部送信なし。フォルダー設定は設定機能の公開境界を使用する。
- **テスト**: `flutter_test`、`integration_test`、実ファイルを用いたテスト。各振る舞いはTDDで実装し、実Android提供元での保存・復旧検証を公開ゲートとする。
- **対象 / 種別**: Android 17（API 37）以降のFlutterモバイルアプリ。現状のAndroid設定はFlutter既定値であり、最低対応バージョンを満たす設定と実端末での確認は未実施。
- **性能**: [仕様](./spec.md)のSC-006に定める固定構成の未完了Todo 1,000件について、指定のPixel 9aエミュレーターで再起動後の初回表示を3回測り、すべて10秒以内とする。ホスト、エミュレーター、データおよび保存先の条件はSC-006とAssumptionsを参照する。
- **制約**: 全サブフォルダー、検索条件保持、対象外テキストの保持、部分読込失敗の通知、外部変更検出、保存失敗・中断時の元データ保護、アクセシビリティ。仕様のSC-001〜007を検証する。
- **規模**: 一覧とその操作・画面遷移の境界。作成・編集・詳細・設定の内部実装は対象外。

**設計上の選択**: NFC比較はAndroid標準の`java.text.Normalizer`をまとめて呼び出す境界を設け、元の表記は保持する。Markdownは位置付き解析と限定編集を行い、判定不能・安全に編集できない場合は拒否する。保存は条件付きコミットと中断復旧を保証できる提供元だけで有効化し、それ以外は閲覧専用とする。具体的な方式の実現可能性と検証条件は[調査](./research.md)を参照する。

## 憲章チェック

| 原則 | Phase 0 前 | Phase 1 後の設計と実装時のゲート |
|---|---|---|
| I. 要件とユーザーデータ | 確認後に適合: 仕様FR-002に合わせてMarkdown互換ルールを修正。 | 対象を指定フォルダーに限定し、形式保持、ファイル単位の失敗、外部変更と安全な保存を検証する。保存保証を実現できないプロバイダーでは書き込みを拒否する。 |
| II. 機能単位 | 適合 | `features/todo` 内に一覧・型付きモデル・Repositoryを置き、設定と遷移は公開境界を使用する。UIに解析やファイル操作を持ち込まない。 |
| III. シンプルさ | 適合 | サーバー・DB・不要な抽象化を追加しない。追加パッケージは保持とAndroidアクセスに必要な場合に根拠を示す。 |
| IV. テスト | 適合 | 仕様ごとにテストリストを作り、Redを実測してからGreen/Refactor。Fakeに加え実ファイル・Android端末で保存、競合、権限と失敗を検証する。 |
| V. 日本語 | 適合 | 成果物、利用者への状況・対処表示は日本語とする。 |

**設計後ゲート: 適合、公開は検証待ち**。利用者の確認により仕様FR-002を採用し、[Markdown互換ルール](../../agents/rules/flutter-todo/data-markdown-compatibility.md)と整合している。通常のMarkdownリンクを編集する際もリンク先と対象外の書式を保持し、安全に位置を特定できない場合は更新を拒否する。安全な保存能力は提供元の明示的保証と実験の両方を必要とし、未確認の間は閲覧専用とする。少なくとも一つの実際のAndroid保存先で両方向の更新、失敗、強制終了、端末再起動と復旧をSC-003どおり検証できなければ公開不可。最低対応バージョンのSC-007も公開ゲートとする。複数のTodoの一括更新は行わない。復旧用データは対象ファイルと合わせて管理するため、その順序・途中失敗・削除も検証する。

**実現可能性の未検証事項**: 上記の条件を保証できる具体的なAndroid保存先・条件付き確定APIはまだ特定できていない。SAFの一般契約に原子的置換や競合制御の保証はなく、実験の成功だけでは保証の代わりにならない。候補の保証と実装方式を示せない場合、この仕様を満たす更新機能は公開できない。
