# テストではシンプルなFakeを優先する

リポジトリやファイル選択などの依存をテストする際は、複雑なモックの入れ子よりも、必要な公開インターフェースを実装するFakeを優先してください。
FakeとMockのどちらも使える場合は、まずFakeで必要な振る舞いを検証できるか検討し、相互作用の検証などで必要な場合にMockを使います。

## ルール

- Fakeは本番コードと同じ契約を実装し、テストが必要とする振る舞いを明示する
- Fakeで隠れている失敗をテストしたい場合は、失敗を返すケースを別途用意する
- 不要な機能まで再現する大規模なテスト用フレームワークを追加しない
- Fakeを使ったテストに加え、実ファイルの解析・保存を一時ディレクトリ等で検証するテストを用意する
