# エンジニアリングルール

このディレクトリには、モジュール化された機械可読なエンジニアリングルールを格納します。

## 構成

ルールは `_sections.md` で定義されているセクション接頭辞に従って整理されています。

このリポジトリのFlutterアプリで適用するルールは [`flutter-todo/`](./flutter-todo/README.md) にまとめています。ルート直下の他のルールは参考資料であり、Flutterアプリに適用する際は `flutter-todo/` の技術・保存形式に関するルールを優先してください。

| 接頭辞 | セクション | 重要度 |
|--------|------------|--------|
| `architecture-` | アーキテクチャ | CRITICAL（重大） |
| `quality-` | コード品質 | CRITICAL（重大） |
| `data-` | データ層 | HIGH（高） |
| `api-` | API設計 | HIGH（高） |
| `performance-` | パフォーマンス | HIGH（高） |
| `testing-` | テスト | MEDIUM-HIGH（中〜高） |
| `patterns-` | 設計パターン | MEDIUM（中） |
| `culture-` | チーム文化 | MEDIUM（中） |

## ファイル

- `_sections.md` - セクション、その順序、重要度を定義する
- `_template.md` - 新しいルールを作成するためのテンプレート
- `{section}-{rule-name}.md` - 個別のルールファイル

## ルールの形式

各ルールファイルは、YAMLフロントマターを含む統一された形式に従います。

```markdown
---
title: ルールのタイトル
impact: CRITICAL | HIGH | MEDIUM | LOW
impactDescription: 任意の説明（例: "20-50%の改善"）
tags: タグ1, タグ2, タグ3
---

## ルールのタイトル

**影響度: レベル（任意の説明）**

ルールの概要と、そのルールが重要な理由を簡潔に説明します。

**誤り（説明）:**
\`\`\`typescript
// 悪いコードの例
\`\`\`

**正しい例（説明）:**
\`\`\`typescript
// 良いコードの例
\`\`\`

参考: [リンク](URL)
```

## 新しいルールの追加

1. `_template.md` を適切なセクション接頭辞を付けた新しいファイルにコピーする
2. フロントマター（タイトル、重要度、タグ）を記入する
3. ルールを明確に説明する
4. 誤った例と正しい例を記載する
5. 該当する場合は参考リンクを追加する

## 利用方法

これらのルールは、次のように活用できるよう設計されています。
- **人が読みやすい:** エンジニアが参照し、学ぶことができる
- **機械可読である:** AIエージェントが解析し、適用できる
- **モジュール化されている:** 他のルールに影響を与えずに個別のルールを更新できる
- **バージョン管理できる:** 変更がGitの履歴に記録される

## 基本原則

私たちのエンジニアリング哲学は次のとおりです。

> 私たちは、ほとんど失敗することのない基盤を構築しています。それを実現するため、近道や妥協をせず、素晴らしい品質のソフトウェアをすばやく提供します。

このディレクトリのルールは、この哲学を実現するための具体的な実践方法を定めています。
